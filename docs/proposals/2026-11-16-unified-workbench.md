# CaptureIT 통합 개선안 — 하나의 작업대

- 작성일: 2026-11-16
- 기준: 커밋 `f4b6408`의 `extension/` 코드와 `PRD.md`, `docs/verification/`
- 근거: 코드·문서 정적 분석. 실제 브라우저에서 실행해 확인한 내용은 없다.
- 용어: 이 문서에서 AX는 AI·에이전트 경험, 즉 AI가 사용자의 일을 대신 진행하는 방식과 사용자가 그 결과를 통제하는 방식을 뜻한다.

## 1. 결론

세 문제는 원인이 같다. 지금 제품은 **증적이 어떤 경로로 들어왔는지, 지금 몇 단계인지, 무엇을 만들려는지**에 따라 화면이 갈린다. 사용자가 다루는 대상은 언제나 증적 하나인데, 화면은 경로마다 따로 있다.

개선안은 이것을 세 가지로 합친다.

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 입력 | 확장 캡처만 1급, 파일 불러오기는 맥락 없음, 붙여넣기는 없음 | 어떤 경로로 들어와도 같은 증적 수집함, 붙여넣기가 1급 입력 |
| 화면 | 편집기 탭의 3단계 + 다이얼로그 7개 + 별도 뷰어 페이지 | 테스트 화면 옆 작업대 하나, 목적은 내보내기에서 선택 |
| AI | 5곳에서 제각각 실행, 판정까지 기록 | 진입점 하나, AI는 초안만 만들고 사람이 확정 |

가장 먼저 할 일은 **붙여넣기 입력 추가**와 **AI가 판정을 기록하는 코드 제거**다. 둘 다 구조 변경 없이 가능하고(6장 1단계), 문제 ②를 바로 해소한다.

## 2. 현재 상태 진단

### 2.1 문제 ① UX가 유려하지 않음

| 현상 | 근거 |

단계는 지금까지 5 → 4 → 3으로 줄어 왔다(`docs/verification/2026-07-08-lazy-user-lifecycle-qa.md`). 단계를 나눌수록 정보가 사라지는 문제가 반복됐다는 뜻이고, 이 방향의 끝은 화면 하나다.

### 2.2 문제 ② 확장이 동작하지 않는 화면

| 현상 | 근거 |
|---|---|
| 붙여넣기 경로가 없다 | `extension/` 전체에 `paste`·clipboard 처리 코드가 0건 |
| 끌어다 놓기는 2단계 수집함에서만 된다 | `editor.js:2713` `#evidence-drop-zone`에만 바인딩. 1단계에는 파일 선택 버튼뿐 |
| 불러온 이미지는 맥락이 파일명뿐이다 | `editor.js:1952` `context: { pageTitle: file.name, … }`. 검색, 단계 묶기, AI 추천에 쓸 정보가 없다 |
| 수집 시각이 파일 수정 시각이다 | `editor.js:1945` |
| 확장이 동작하지 않는 화면인지 알려주지 않는다 | 콘텐츠 스크립트 호출 실패를 `.catch(() => {})`로 넘긴다. 수집을 켜도 아무것도 쌓이지 않아 고장으로 보인다 |

그래서 지금은 OS 캡처 도구로 찍은 화면을 **파일로 저장한 뒤 불러와야** 하고, 그렇게 넣은 증적도 확장으로 수집한 증적보다 취급이 떨어진다.

### 2.3 문제 ③ 목적마다 다른 UI

| 목적 | 지금 가는 길 |

## 3. 개선안

### 3.1 작업대를 테스트 화면 옆에 둔다

작업대를 탭이 아니라 브라우저 사이드 패널에 둔다. 테스트 화면과 작업대가 동시에 보인다.

```
┌ 테스트 화면 (어떤 화면이든) ─────────────────┐┌ CaptureIT ────────────────┐
│                                            ││ ● 자동 수집 중       [중지]  │
│                                            ││ 수집 대상: 2. 주문 승인  ▾   │
│                                            ││ ┌────┐ ┌────┐ ┌────┐       │
│                                            ││ │ #7 │ │ #8 │ │ #9 │  …    │
│                                            ││ └────┘ └────┘ └────┘       │
│                                            ││ 스크린샷은 여기에 Ctrl+V     │
│                                            ││ ────────────────────────── │
│                                            ││ 증적 9 · 테스트케이스 2      │
│                                            ││ [AI로 정리]    [내보내기 ▾]  │
└────────────────────────────────────────────┘└────────────────────────────┘
```

- 탭 왕복이 없어지고, 2.1의 우회 로직 3개와 "탭을 찾을 수 없습니다" 오류의 원인이 사라진다.
- 확장이 동작하지 않는 화면이나 브라우저 밖 프로그램을 테스트할 때도 패널은 그대로 있어서, 찍고 바로 붙여넣을 수 있다.
- 패널 폭에서는 수집에 필요한 것만 보이고, "넓게 보기"를 누르면 같은 페이지가 탭으로 열려 정리 화면이 된다. 페이지와 상태는 하나이고 레이아웃만 폭에 따라 바뀐다.

사이드 패널을 쓸 수 없는 환경이면 같은 페이지를 작은 창으로 옆에 띄운다. 구조는 같다.

### 3.2 입력을 하나의 증적 수집함으로 합친다

경로가 무엇이든 같은 함수로 같은 증적을 만든다.

| 경로 | 쓸 수 있는 곳 | 맥락을 얻는 방법 |
|---|---|---|
| 자동 수집 | 확장이 동작하는 화면 | DOM·URL·순서 (현행) |
| 강조 캡처 | 확장이 동작하는 화면 | 대상 요소 (현행) |
| **붙여넣기 (신규)** | 어디서든 | 아래 "맥락 보강" |
| 끌어다 놓기 | 어디서든. 작업대 전체가 놓는 곳 | 아래 "맥락 보강" |
| 파일 선택 | 어디서든 | 아래 "맥락 보강" |

**붙여넣기**

- 작업대 어디서든 Ctrl+V. 페이지의 `paste` 이벤트로 받으므로 추가 권한이 필요 없다. 글자 입력란에 커서가 있고 붙여넣는 것이 글자면 가로채지 않는다.
- 붙여넣을 때마다 순번을 주고, 연속으로 붙여넣은 것은 한 묶음으로 잇는다. 지금의 수집 묶음 표시(Capture_Graph)를 그대로 쓴다.
- 수집 시각은 붙여넣은 시각으로 기록한다.
- 같은 이미지를 연달아 붙여넣으면 한 번만 받고, 잘못 넣은 것은 되돌리기로 뺀다.

**확장이 동작하지 않는 화면을 알아채서 안내를 바꾼다**

패널이 현재 탭에 맥락을 물어보고(이미 있는 `COLLECT_PAGE_CONTEXT`), 응답이 없으면 상태 줄을 바꾼다.

```
이 화면은 자동 수집이 되지 않습니다.
화면을 캡처한 뒤(Win+Shift+S) 여기에 Ctrl+V 하세요.
```

수집 시작 버튼 대신 붙여넣기 영역이 주 행동이 된다. 사용자가 고장인지 고민할 일이 없다.

**맥락 보강: 붙여넣은 증적을 같은 급으로 만든다**

1. 수집 대상 테스트케이스가 정해져 있으면 바로 거기에 연결한다(3.3).
2. 직전 증적의 화면 이름을 이어받을지 한 번 묻는다. 같은 화면을 여러 장 찍는 경우가 많다.
3. 한 줄 메모를 받는다. 선택이며 Enter로 건너뛴다.
4. AI 화면 읽기(3.4). 이미지에서 화면 제목, 주요 문구, 단계 유형을 읽어 맥락으로 저장한다. AI가 읽은 값이라는 표시를 남긴다.

**클립보드로 내보내기**

붙여넣기의 반대 방향도 연다. 증적 이미지 복사, 테스트케이스 결과 표 복사를 넣으면 ZIP을 받지 않는 양식이나 Excel에도 바로 붙일 수 있다.

**선택 사항: 화면 공유 캡처**

브라우저의 화면 공유 API로 창 하나를 한 번 골라 두면, 버튼 한 번으로 그 창의 현재 화면을 증적으로 넣을 수 있다. 브라우저 밖 프로그램도 된다. 다만 `PRD.md`의 비목표("앱 또는 레거시 빌더 화면의 직접 캡처")를 바꾸는 결정이고 사내 정책 확인이 필요해 기본안에서는 뺐다.

### 3.3 화면은 하나, 목적은 내보내기에서 고른다

단계 탭을 없애고 한 화면에 증적 수집함과 테스트케이스를 나란히 둔다.

```
┌ CaptureIT · [주문승인 QA ▾]                              저장됨 · 설정 ┐
├──────────────────────────────┬──────────────────────────────────────┤
│ 증적 수집함 (12)     [검색]    │ 테스트케이스 (3)                 [+]  │
│ ▾ 자동 수집 14:02 (7)         │ 1. 로그인      PASS    ▣▣▣           │
│   #1 #2 #3 #4 #5 #6 #7       │ 2. 주문 승인   미판정   ▣▣  ← 수집 대상 │
│ ▾ 붙여넣기 14:10 (3)          │    설명 [AI 초안] …            [확정] │
│   #8 #9 #10                  │    기대 / 실제 / [PASS][FAIL][미판정]  │
│ ▾ 미분류 (2)                  │ 3. 반려        미판정   증적 없음      │
├──────────────────────────────┴──────────────────────────────────────┤
│ ● 자동 수집 중 [중지]   Ctrl+V 붙여넣기   [AI로 정리]    [내보내기 ▾]   │
└─────────────────────────────────────────────────────────────────────┘
```

**목적은 "내보내기"의 선택지다**

| 내보내기 | 필요한 것 | 지금 있는 곳 |
|---|---|---|
| 증적 묶음 ZIP | 증적 1개 이상 | 더보기 → 저장 정보 보기 |
| QA 보고서 ZIP | 테스트케이스, 연결, 판정. 부족해도 경고만 하고 막지 않는다 | 3단계 |
| 클립보드로 복사 | 선택한 증적 또는 결과 표 | 없음 |
| 작업 백업 | 없음 | 더보기, 3단계 |

**단계 대신 준비 상태를 보여준다**

각 선택지 옆에 지금 상태를 적는다. 예: "QA 보고서 — 미판정 2건, 증적 없는 항목 1건". 누르면 해당 항목으로 이동한다. 이미 있는 `validationWarnings`를 그대로 쓴다. 사용자는 "지금 몇 단계인가"가 아니라 "내가 만들려는 것에 무엇이 남았나"를 본다.

**수집 대상을 먼저 정할 수 있다**

테스트케이스 하나를 수집 대상으로 정해 두면, 그동안 수집하거나 붙여넣은 증적이 바로 거기에 연결된다. 무엇을 테스트하는지 알고 시작하는 사용자에게는 연결 작업이 없어진다. 지금처럼 일단 모으고 나중에 정리하는 방식도 그대로 된다.

**뷰어를 같은 작업대로 합친다**

작업대에 ZIP을 끌어다 놓으면 읽기 전용 보기로 연다. 이미지면 증적, ZIP이면 열람이다. 넣은 것이 목적을 정하므로 뷰어를 찾아 들어갈 필요가 없다. `viewer.js`의 검증·격리 로직은 그대로 쓴다.

**나머지 진입점 정리**

- 보고서 전환과 새 보고서: 헤더의 보고서 이름을 누른다.
- 저장 정보, AI 설정: 설정 하나로 모은다.
- 빈 화면: 문장 하나와 입력 영역 하나. "수집을 시작하거나, 스크린샷을 붙여넣거나, 받은 ZIP을 끌어다 놓으세요."

### 3.4 AX: AI 개입을 한 가지 규칙으로 맞춘다

**규칙: AI는 정리하고, 사람이 판정한다.** AI가 만든 것은 모두 초안으로 들어오고, 사용자가 확정해야 보고서에 반영된다.

| 항목 | 내용 |
|---|---|
| 판정 | AI는 판정을 기록하지 않는다. 대신 판정 버튼 옆에 "AI 의견: PASS, 근거 …"를 참고로 보여준다 |
| 진입점 | [AI로 정리] 하나. 드로어의 버튼 2개와 자동 다이얼로그는 여기로 합친다 |
| 하는 일 | ① 붙여넣은 증적의 화면 읽기 ② 증적 묶기와 테스트케이스 후보 제안 ③ 증적 연결 제안 ④ 설명·기대·실제 결과 초안 ⑤ 보고서 제목·개요 초안 |
| 실행 시점 | 사용자가 눌렀을 때. 자동 실행을 원하면 설정에서 직접 켠다 |
| 검토 | 제안을 항목별로 수락·거절하고, 전체 수락도 된다. 사용자가 이미 쓴 내용은 덮어쓰지 않고 나란히 보여준다 |
| 출처 표시 | 필드마다 AI 초안, 직접 입력, 확정을 구분한다 |
| 전송 범위 | 실행 전에 "이미지 N장과 텍스트 맥락 M건을 내부망 게이트웨이로 보냅니다"를 한 줄로 알린다. 이미지 수 제한은 기존 `selectTopImages`를 쓴다 |
| AI가 없을 때 | 같은 버튼이 규칙 기반으로 ②까지 한다. 수집 묶음·화면·시간 간격으로 묶는 코드(`groupIntoCaptureSessionSets`, `buildEvidenceSteps`)가 이미 있다 |

**행동을 한 곳에 정의한다**

수집 시작, 붙여넣기, 연결, 판정, 내보내기 같은 행동을 이름·실행 조건·처리 함수의 목록 하나로 정의한다. 버튼, 단축키, AI 제안의 "적용"이 모두 이 목록을 부른다. `wizard-stage.js`의 `planActions`가 출발점이다. 이렇게 하면 화면에 보이는 행동과 AI가 제안할 수 있는 행동이 어긋나지 않고, 나중에 사내 에이전트가 같은 목록으로 작업대를 다룰 수 있다. 판정 행동은 AI와 에이전트에게 열지 않는다.

### 3.5 다듬기

- 판정은 [PASS] [FAIL] [미판정] 버튼 3개로 나누고 단축키를 붙인다.
- 삭제, 연결 해제, 붙여넣기는 확인 창 없이 실행하고 되돌리기를 준다.
- 수집 상태, 저장 상태, AI 진행은 하단 한 줄에 모은다.
- 용어를 "수집"으로 통일하고 내부 식별자를 문구에서 뺀다. `RECORDING` → 수집 중, `N/A` → 미판정, "기능 명세" → 테스트케이스.
- 수집 알림 토스트의 `click`, `route-change` 같은 원문을 "클릭 후 화면", "화면 전환"으로 바꾼다.
- 입력란이 없는 "검증 내용" 경고는 없애거나 입력란을 되살린다.

- 모든 변경은 브라우저 내장 기능만 쓴다. 외부 라이브러리와 외부 통신이 없어 폐쇄망 조건(NFR-02)은 그대로다.

## 7. 목적 확장: PASS/FAIL 밖의 쓰임

사내에서는 QA 결과 보고 말고도 PoC 협업, 단위·통합 테스트, 제안 설명에 쓰인다. 목적이 달라도 **화면을 모으고 순서대로 정리해서 설명을 붙인다**는 부분은 같다. 다른 것은 항목 하나에 무엇을 적는지, 판정이 있는지, 어떤 모양으로 내보내는지뿐이다.

### 7.1 수집·정리·내보내기를 나누고, 목적은 "문서 유형"으로 둔다

| 층 | 목적에 따라 바뀌는가 | 내용 |
|---|---|---|
| 수집 | 아니다 | 녹화, 강조 캡처, 붙여넣기, 중복 합치기. 지금 그대로 |
| 정리 | 문서 유형이 정한다 | 항목 이름, 항목마다 적는 칸, 상태 값 |
| 내보내기 | 문서 유형이 정한다 | HTML 배치와 표 구성 |

문서 유형은 작업(지금의 보고서) 하나에 붙는 속성이다. 처음에 한 번 고르고 언제든 바꿀 수 있다. 바꿔도 공통 칸(제목, 설명, 연결된 증적)은 그대로 옮겨 가고, 새 유형에 없는 칸은 지우지 않고 숨긴다.

| 문서 유형 | 항목 | 항목의 칸 | 상태 | 내보내기 | AI가 돕는 일 |
|---|---|---|---|---|---|
| QA 결과 보고 (현행) | 테스트케이스 | 설명, 기대 결과, 실제 결과 | PASS · FAIL · 미판정 | 지금의 보고서 | 설명·기대·실제 결과 초안 |
| 단위·통합 테스트 결과서 | 테스트 케이스 | 사전조건, 테스트 데이터, 절차(화면 순서), 기대, 실제 | PASS · FAIL · 보류 · 해당없음 | 결과 표 + 단계별 화면 | 수집 순서로 절차 단계 초안 |
| PoC 확인 기록 | 확인 포인트 | 확인하려던 것, 확인 결과, 질문·후속 | 확인됨 · 부분 확인 · 미확인 | 확인 포인트 표 + 질문 목록 | 결과 요약, 열린 질문 정리 |
| 제안·화면 설명서 | 장면 | 설명 문구, 강조할 곳 | 없음 | 장면 순서대로 넘겨 보는 HTML | 장면 설명 문구 초안 |

통합 테스트의 "절차"는 이미 있는 수집 묶음(Capture_Graph)과 화면 단계 묶기(`buildEvidenceSteps`)를 그대로 쓴다. 제안 설명서의 "강조할 곳"은 강조 캡처(빨간 테두리)가 이미 해 준다.

### 7.2 데이터와 산출물

- 지금의 `features[].result`(검증·기대·실제·status)를 QA 유형의 칸 묶음으로 보고, 다른 유형은 같은 자리에 유형별 칸을 둔다. 항목, 증적 연결, 순서는 모든 유형이 같은 구조를 쓴다.
- `manifest.json`에 `documentType`을 추가하고 `schemaVersion`을 올린다. QA 유형은 지금과 같은 구조로 내보낸다.
- **주의:** 뷰어가 `schemaVersion !== 1`이면 열기를 거부한다(`extension/shared/viewer.js:15`). 새 유형의 ZIP을 받는 사람의 확장도 같이 올라가야 하므로, 뷰어 갱신을 먼저 배포한다.
- 판정이 있는 유형만 전체 결과(PASS/FAIL/INCOMPLETE)를 계산한다. 제안 설명서에는 요약 칸 자체가 없다.

### 7.3 화면

- 새 작업을 만들 때 문서 유형 네 개 중 하나를 고른다. 기본은 QA 결과 보고다.
- 항목 카드의 칸과 상태 버튼만 유형에 따라 바뀌고, 수집함·연결·중복 정리·붙여넣기는 모두 같다.
- 내보내기 메뉴의 "QA 보고서 ZIP"이 "문서 ZIP"이 되고, 증적 묶음 ZIP·복사·백업은 유형과 무관하게 남는다.
- AI 원칙(3.4)은 유형과 상관없이 같다. AI는 칸을 채우는 초안만 만들고, 상태는 사람이 정한다.

### 7.4 산출물 형식

HTML을 기본으로 하고, 표를 다뤄야 하는 유형에만 엑셀을 함께 넣는다. 유형별 화면 모양과 엑셀 칸 구성은 [document-templates-sample.html](document-templates-sample.html)에 예시로 그려 두었다.

- 엑셀은 모든 유형이 **요약 · 목록 · 증적** 세 시트로 같은 구성을 쓴다. 목록 시트의 칸만 유형마다 다르다.
- 상태 칸은 목록 선택, 머리글 고정과 필터를 켜 두고, 썸네일은 증적 시트에만 넣는다. 원본 이미지는 ZIP의 `assets/`로 연결한다.
- 제안 설명서는 엑셀 대신 16:9 장면 HTML을 쓴다. 브라우저 인쇄로 PDF가 된다.
- xlsx도 ZIP 형식이라 지금 있는 `extension/shared/zip.js`로 만들 수 있다. 외부 라이브러리가 필요 없어 폐쇄망 조건은 그대로다. 다만 PRD가 Excel 산출물을 비목표로 두고 있으므로 PRD를 함께 고쳐야 한다.

**문서 양식(지면 모양)은 문서 유형과 따로 고른다.** 3.0.0에 다섯 가지를 넣었다. 마크업은 같고 CSS만 다르며, 고른 양식은 보고서에만 저장되고 manifest에는 들어가지 않는다. 판정은 칩 대신 기호와 글자(✓ PASS, ✕ FAIL, ○ 미판정)로 표기한다. 비교는 [report-templates-preview.html](report-templates-preview.html)에서 할 수 있다(로컬 서버로 저장소 루트를 띄워 열어야 생성기 스크립트를 불러온다).

| 양식 | 쓰임 |
|---|---|
| 에디토리얼 (기본) | 제목 서체와 괘선, 그림 캡션. 읽는 문서 |
| 공문서 | 격자 표와 음영 머리칸, 이중선 제목. 결재·제출 |
| 표 중심 | 작은 글씨와 작은 그림, 칸 두 줄 배치. 케이스가 많을 때 |
| 그림 중심 | 화면을 크게 한 장씩, 인쇄 시 케이스마다 새 쪽. 리뷰·발표 |
| 흑백 인쇄 | 색과 채움 없이 검정, FAIL은 밑줄. 흑백 출력·팩스 |

### 7.5 협업(PoC)

PRD는 서버 저장과 공동 편집을 비목표로 둔다. 서버 없이 할 수 있는 범위는 **ZIP을 주고받으며 의견을 붙이는 것**이다. 받은 사람이 뷰어에서 장면이나 항목에 의견을 달면 `review.json`으로 내보내고, 작성자가 그 파일을 작업대에 끌어다 놓으면 항목 옆에 의견이 붙는다. 실시간 공동 편집이 필요하면 사내 서버가 필요하므로 별도 결정이다.

### 7.6 순서

1. 데이터에 문서 유형을 넣고 QA 유형만 둔다. 동작 변화는 없다. 뷰어가 새 버전을 읽도록 같이 고친다.
2. 제안·화면 설명서. 판정이 없어 가장 단순하고, 강조 캡처와 수집 순서를 그대로 쓴다.
3. 단위·통합 테스트 결과서.
4. PoC 확인 기록과 의견 파일 주고받기.

## 8. 확인과 결정이 필요한 것

확인된 사항(2026-11-16):

- 확장이 동작하지 않는 화면은 **다른 브라우저**와 **Edge IE 모드 화면**이다. Edge·Chrome이 띄운 팝업·새 창은 같은 브라우저의 탭이므로 http(s) 주소면 자동 수집이 된다. IE 모드 탭은 주소가 http(s)여도 콘텐츠 스크립트가 돌지 않으므로, 녹화 시작 시 이를 감지해 붙여넣기 안내로 바꾼다(1단계에 반영).
- 사내 Edge는 142.0.3595로 사이드 패널(`chrome.sidePanel`)을 쓸 수 있다. 3단계는 작은 창 대안 없이 사이드 패널로 진행한다.
- 이벤트 수집이 너무 많이 찍혀 정리에 시간이 든다. 1단계에 중복 화면 합치기(수집 시점)와 중복 화면 정리(이미 쌓인 것)를 추가했다.

남은 항목:

| 항목 | 왜 필요한가 |
